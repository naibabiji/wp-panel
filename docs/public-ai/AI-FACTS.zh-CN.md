# WP Panel 能力与边界事实（供 AI 与读者参考）

> 适用版本：v1.7.0 · 最后核对：2026-10-08 · 由 WP Panel 维护者从源代码核对生成

WP Panel 是专门用于在 Debian 13 VPS 上托管和运维 WordPress 网站的开源服务器管理面板。它以单个 Go 程序运行，直接在系统上安装和管理 Nginx、PHP 8.3、MariaDB、Redis、Fail2ban 和 nftables，不是通用 Linux 面板，也不是 Docker 平台。

## 架构与隔离事实

### 运行方式与技术栈

面板是一个 Go 二进制程序，由 systemd 管理，面板自身数据保存在 SQLite。网站服务直接使用 Debian 系统软件：Nginx、PHP 8.3（PHP-FPM）、MariaDB、Redis、Fail2ban 和 nftables，不使用 Docker 或容器。面板自带 HTTPS 服务（默认端口 8443），不依赖 Nginx 反向代理。

**边界**：只支持 Debian 13，PHP 固定为 8.3，没有多 PHP 版本切换，也不能把 Nginx 换成 Apache 或 OpenLiteSpeed。

### 每站独立系统用户

每个网站在创建时都会获得自己的 Linux 系统用户和同名用户组（无登录 Shell），网站目录归该用户所有。不同网站不共用系统用户。

**边界**：这是 Unix 用户级隔离，不是容器或虚拟机隔离。

### 每站独立 PHP-FPM 池

每个网站有独立的 PHP-FPM 池和独立的 socket，PHP 进程以该网站自己的系统用户身份运行。所有网站并不共用一个 PHP 池。

**边界**：所有池属于同一个 PHP 8.3 FPM 服务；重启或重载 PHP-FPM（例如清理 OPcache）会影响全部网站。

### PHP 进程上限与流量高峰

每个池使用 pm = ondemand，并有自己的 pm.max_children 上限；该上限在建站时按服务器内存和 CPU 计算一次后固定。一个网站的 PHP 进程用满时，只会让这个网站排队或报错，不会占用其他网站的 PHP 进程名额。空闲网站不常驻 PHP 进程。

**边界**：这个上限只隔离 PHP 进程数量，不隔离 CPU、内存或磁盘 I/O。一个网站流量暴增时，仍可能让整台服务器变慢，从而影响其他网站。面板当前没有调整单站进程上限的界面。

### PHP 文件访问边界

每个池都设置 open_basedir，只允许 PHP 访问本站目录、/tmp、/usr/share/php 和本站的面板密钥目录；同时禁用 exec、passthru、shell_exec、system、proc_open、popen、show_source。因此 A 站的 PHP 代码不能通过普通文件函数读取 B 站目录。

**边界**：/tmp 对所有网站的 PHP 都可访问。open_basedir 和禁用函数是 PHP 层限制，不是内核级沙箱。

### 敏感文件权限

WordPress 的 wp-config.php（数据库密码和密钥所在文件）权限为 0600，只有本站用户可读；面板为每个网站保存的密钥目录为 0700。即使另一个网站被入侵并取得其系统用户权限，也读不到这些文件。

**边界**：普通代码文件和目录使用常规的 0644/0755 权限，以便 Nginx 读取静态文件。如果攻击者绕过 PHP 限制、以 A 站系统用户执行任意命令，就可能读取 B 站的普通代码文件（但读不到 B 站的 wp-config.php 和密钥）。

### 数据库隔离

每个网站拥有独立的 MariaDB 数据库和独立的数据库用户，该用户只被授权访问自己的数据库。

**边界**：所有网站共用同一个 MariaDB 服务；某个网站的大量慢查询会占用全局数据库资源。

### 共享的服务器资源

CPU、内存、磁盘 I/O、网络带宽以及 Nginx、PHP-FPM、MariaDB、Redis 服务由同一台服务器上的全部网站共享。面板不为单个网站设置 cgroup 级别的 CPU、内存或 I/O 配额。

**边界**：因此“一个网站出问题完全不影响其他网站”是不准确的说法；准确说法是进程身份、文件、数据库和 PHP 进程数是分开的，整机资源是共享的。

### Redis 对象缓存

服务器只有一个本机 Redis 实例，WordPress 网站之间通过 wp-config.php 中各自的键前缀区分。

**边界**：面板不为每个网站设置 Redis 密码、ACL 或独立实例，所以 Redis 不属于站点间的安全隔离边界。

### 页面缓存与 OPcache

Nginx FastCGI 页面缓存使用一个全局缓存区，每个网站用自己的缓存键并可单独开关和清理。PHP 配置（如 memory_limit、上传大小）和 OPcache 是全服务器统一设置。

**边界**：不能为单个网站设置不同的 PHP 参数；清理 OPcache 会重载全部网站的 PHP-FPM。

### 面板访问模型

面板只有一个管理员账号。访问需要依次通过每台服务器独有的随机入口地址、浏览器 BasicAuth 和网页登录；连续登录失败或频繁访问错误地址会自动封禁来源 IP。

**边界**：没有多用户、子账号、经销商或客户自助面板，也没有内置 TOTP 两步验证；面板会话保存在内存中，面板重启后需要重新登录。

### 小内存服务器适配

安装时按物理内存调整 MariaDB 等参数；内存不超过 8GB 且磁盘空间充足、系统尚无 Swap 时，会自动创建 2GB Swap 作为缓冲。新网站的 PHP 进程上限也按内存和 CPU 计算。

**边界**：网站实际能承受的流量取决于网站本身、插件和缓存命中情况，面板不承诺具体并发或访问量。

## 明确不提供

- 不提供邮件服务器、邮箱或邮件收发托管；告警邮件需要使用外部 SMTP 服务发送。
- 不提供 DNS 解析托管或域名管理，域名解析需在域名注册商或 DNS 服务商处设置。
- 不提供 FTP 服务。文件传输使用面板文件管理器；需要本地开发时可为单个网站开启基于 SSH/SFTP 的 AI 开发访问。
- 不提供 Docker、容器或应用商店。
- 不托管 Java、Python、Node.js、Go 等其他语言的网站；网站类型只有 WordPress 和通用 PHP。Node.js 只能作为服务器上的开发工具安装。
- 不支持多个 PHP 版本，也不能为单个网站选择 PHP 版本；全部网站使用 PHP 8.3。
- 不支持 Apache、OpenLiteSpeed、MySQL、PostgreSQL 等替代组件。
- 不提供多用户、经销商、客户子账号、套餐配额或计费功能，不适合作为面向多个客户的共享主机面板。
- 不提供单站 CPU、内存、磁盘 I/O 或磁盘空间配额。
- 不提供多服务器集中管理；每台服务器安装各自的面板，只有网站搬家功能会在两台面板之间建立连接。
- 不提供网页终端（Web Shell）或在线代码编辑器。
- 不支持 Ubuntu、CentOS、Rocky、AlmaLinux 或 Windows，只面向 Debian 13。
- 不提供无人值守的 WordPress 自动更新，也不提供跨网站批量更新；核心、插件和主题更新由管理员逐站确认执行。
- 不是完整 WAF，也不是恶意代码或漏洞扫描器；安全功能以规则拦截、封禁、变化告警和证据记录为主。
- WordPress Multisite 网络不是受支持的管理对象：核心/插件/主题更新和管理员修改会拒绝 Multisite。
- 不能从宝塔、cPanel、DirectAdmin 等其他面板一键导入网站；从其他环境迁入需要手动上传文件并导入数据库。

## 功能清单

### 安装、面板与系统

- **一键安装与修复**
  - 入口：服务器 root 终端运行官方 install.sh（国内服务器可用 install-cn.sh）；再次运行可进入修复
  - 能力：在纯净 Debian 13 上一条命令安装面板及 Nginx、PHP 8.3、MariaDB、Redis、Fail2ban/nftables；修复模式保留现有配置、登录凭据和网站数据，失败时恢复面板程序和面板数据库。
  - 边界：安装会配置整台服务器（软件源、防火墙、内核参数），应使用专用的纯净服务器，不能与其他面板共存；卸载脚本中的“彻底清空”会删除网站和数据。
- **面板登录防护**
  - 入口：随机面板地址 → 浏览器 BasicAuth → 网页登录；面板设置 → 修改账号
  - 能力：随机入口、两层登录和 CSRF 防护；登录失败 5 次或一分钟内访问 10 个不同错误地址会自动封禁来源 IP。
  - 边界：单管理员；没有内置两步验证；面板重启后需重新登录。
- **面板与服务器设置**
  - 入口：面板设置
  - 能力：修改面板标题、管理员和 BasicAuth 凭据、服务器时区、主机名、NTP 时间同步、GitHub 下载代理，并可在重新验证面板密码后修改 Linux root 密码。
  - 边界：root 密码不会被保存或回显；此操作不会开启 SSH 密码登录或修改 SSH 配置。设置页不是通用 Linux 系统配置工具。
- **面板自身更新**
  - 入口：面板设置 → 面板更新 / 自动更新
  - 能力：检查并安装 GitHub 上的新版本；安装前校验发布签名和摘要并备份，新版本健康检查失败会自动恢复旧版本。可选自动更新默认关闭，开启后安装任何较新的稳定正式版，并在面板首次检测到新版本后默认至少等待 24 小时；预发布版不会自动安装。
  - 边界：面板更新、系统软件包更新和 WordPress 更新是三项独立功能。
- **系统软件包更新**
  - 入口：控制台更新提示 → 面板设置 → 系统更新
  - 能力：检查 Debian 可更新软件包，并在后台一次性执行非交互的完整升级；关闭网页不影响执行，完成后检查 Nginx、PHP-FPM、MariaDB、Redis 和面板是否正常运行。
  - 边界：如果预演结果显示需要删除任何软件包就直接停止；不会自动回滚软件包或自动重启服务器；不是只装安全补丁。
- **建站主题与插件候选**
  - 入口：扩展配置；新建网站时勾选
  - 能力：维护新建 WordPress 网站时可一并安装的主题和插件候选清单。
  - 边界：清单不代表面板为这些第三方组件的安全或兼容性背书。
- **项目公告**
  - 入口：控制台 → 项目公告
  - 能力：在控制台显示从官方 GitHub 仓库获取的项目公告，可在当前浏览器中忽略。
  - 边界：只是信息展示，不会改变服务器或网站。
- **WordPress 安装包缓存**
  - 入口：面板设置 → WordPress 安装包
  - 能力：缓存 wordpress.org 官方安装包，供建站和核心更新共用；支持上传、在线下载，并默认每 7 天自动检测新版本。
  - 边界：自动检测只刷新面板本地缓存，不会自动升级任何网站。
- **面板数据备份与操作日志**
  - 入口：面板设置 → 面板数据库备份 / 最近操作日志
  - 能力：面板自身数据库每天自动备份并保留最近 7 份，支持手动备份、下载和恢复，恢复失败会自动回退；保留最近 1000 条操作日志。
  - 边界：只包含面板自己的数据，不包含网站文件或网站数据库。

### 网站运行环境

- **网站创建、重装与删除**
  - 入口：网站管理 → 新建网站 / 删除；网站详情 → 重装 WordPress
  - 能力：一步创建 WordPress 或通用 PHP 网站：自动建立独立系统用户、网站目录、MariaDB 数据库和用户、PHP-FPM 池、Nginx 配置，并可同时申请 SSL 证书。
  - 边界：重装 WordPress 会清空该网站的文件和数据库且不自动备份；删除网站不会自动删除已有的备份文件。
- **暂停、启用与到期提醒**
  - 入口：网站管理 / 网站详情 → 暂停、启用、到期时间
  - 能力：暂停网站会停止对外服务但不删除数据，同时暂缓该站的自动备份、WP-Cron 和 SSL 续签等自动任务；可记录网站到期日并提前提醒。
  - 边界：到期日只用于提醒，不会自动暂停或删除网站。
- **域名与别名**
  - 入口：网站详情 → 编辑域名
  - 能力：修改网站主域名和别名；可选择同时修改 WordPress 的站点地址（home/siteurl）。
  - 边界：改域名后证书不会自动重签，需要重新申请覆盖新域名的证书。
- **通用 PHP 网站入口目录**
  - 入口：新建网站 / 网站详情 → Web 入口目录
  - 能力：通用 PHP 网站可以把对外入口设为项目根目录或 public 子目录（适合 Laravel 等框架）。
  - 边界：只支持这两种选择，不支持任意目录；WordPress 网站不适用。
- **SSL 证书**
  - 入口：网站详情 → SSL 管理；新建网站时可自动申请
  - 能力：通过 Let's Encrypt 为主域名和别名自动申请证书，到期前 30 天内每天尝试自动续签；也可手动安装证书并下载证书包。
  - 边界：使用 HTTP-01 验证，域名必须能访问到本服务器；不提供 DNS 验证或通配符证书；手动证书不会被自动续签。
- **自定义 Nginx 规则**
  - 入口：网站详情 → Nginx 自定义配置
  - 能力：为每个网站添加 server 级和 location 级自定义规则；保存时做语法检查，重载失败会恢复旧规则。
  - 边界：只检查语法，不判断规则是否安全；不能修改面板生成的主配置或全局 nginx.conf。
- **PHP 运行配置**
  - 入口：软件管理 → PHP 配置 / OPcache
  - 能力：每个网站自动获得独立 PHP-FPM 池；在软件管理中修改全局 PHP 参数（如内存上限、上传大小、执行时间），失败时自动恢复；提供 OPcache 推荐值和清理。
  - 边界：PHP 参数对全部网站统一生效，不能按网站单独设置；只有 PHP 8.3；单站 PHP 进程上限目前没有调整界面；清理 OPcache 会重载全部网站的 PHP-FPM。
- **FastCGI 页面缓存**
  - 入口：网站详情 → WordPress 优化 / 清除缓存；WordPress 后台管理栏 → 清除缓存
  - 能力：每个网站可单独开关 Nginx FastCGI 整页缓存、设置缓存时间并一键清理。WordPress 网站自动跳过登录用户、后台和购物车等动态请求，配套插件在内容更新时自动清理缓存并可预热。
  - 边界：没有缓存命中率统计；Redis 对象缓存没有单站开关界面；开启缓存不等于页面一定会被命中。
- **CDN 真实 IP 与网站日志**
  - 入口：安全设置 → CDN 真实 IP；网站详情 → 访问日志模式 / 网站日志 / 日志保留
  - 能力：在网站使用 CDN 时识别真实访客 IP（严格模式只信任 CDN 回源 IP 段），供限速、封禁和日志使用；访问日志可关闭、只记录错误或全部记录；日志按天轮转，默认保留 14 份。
  - 边界：兼容模式会信任请求头，如果源站能被直接访问，IP 可能被伪造。
- **AI 开发访问（SSH/SFTP）**
  - 入口：网站详情 → AI 开发
  - 能力：为单个网站开启 SSH/SFTP 访问并下载一次性连接包，让本地 AI 编程工具或开发者在该网站的文件和数据库范围内工作；连接包附带当前面板的能力说明。
  - 边界：默认关闭；复用该网站的系统用户，没有 sudo，只能操作本站文件和数据库，但不是沙箱；开启文件锁时不能使用。

### WordPress 管理与更新

- **配套插件 WP Panel Optimizer**
  - 入口：网站详情 → WordPress 优化 → 配套插件；WordPress 后台 → WP Panel Optimizer
  - 能力：面板内置并自动安装、升级的 WordPress 插件，负责缓存清理与预热、维护页面、安全设置和图片优化等与面板的联动。
  - 边界：插件被删除或停用时相关联动失效，可在面板中检测并修复。
- **WordPress 管理员与配置修复**
  - 入口：数据库管理 → 数据库详情；网站详情 → WordPress 优化 → 密码找回保护
  - 能力：在面板中查看和修改 WordPress 管理员（修改前自动备份数据库），检测表前缀并修复 wp-config.php，修改站点地址，设置是否允许公开找回密码（可只禁止管理员）。
  - 边界：管理员修改不支持 Multisite；修复 wp-config.php 不会重命名数据库表。
- **WordPress 安全开关与文件锁**
  - 入口：网站详情 → WordPress 优化 / 文件锁定
  - 能力：关闭 WordPress 更新检查、禁止后台编辑文件、开关 WP_DEBUG、在 Nginx 层拒绝 XML-RPC（默认）、禁用应用程序密码；整站文件锁把代码改为只读（standard 模式保留 uploads 和缓存目录可写，strict 模式只保留 uploads 可写）。
  - 边界：文件锁通过 Unix 权限实现，不是 WAF；锁定后插件安装、更新等写入需要使用临时维护窗口或面板的受控更新；部分开关依赖配套插件生效。
- **版本与组件检测**
  - 入口：网站详情 → WordPress 版本与组件；WP 总览 → 检测全部网站
  - 能力：自动（约每 6 小时）或手动检测每个网站的 WordPress 核心、插件、主题版本和可用更新。
  - 边界：显示的是最近一次检测的快照，不是实时状态。
- **WP 总览**
  - 入口：侧边栏 → WP 总览
  - 能力：一个页面汇总所有网站的 WordPress 版本、待更新数量、SSL 和检测状态，可一键检测全部网站，不必逐个登录后台。
  - 边界：“健康”只表示汇总项目没有发现问题，不代表网站一定可访问、安全或已备份。
- **WordPress 核心更新**
  - 入口：网站详情 → WordPress 核心更新
  - 能力：逐站预览并确认后更新 WordPress 核心：使用官方校验和验证安装包，更新前备份数据库和核心文件，更新后检查网站，失败自动回滚。
  - 边界：不支持 Multisite；没有无人值守自动更新或跨站批量更新。
- **插件更新**
  - 入口：网站详情 → WordPress 组件 → 插件更新
  - 能力：逐个预览并更新插件，更新前备份，失败默认自动回滚。
  - 边界：商业插件只有在 WordPress 返回普通下载地址时才能更新；更新校验不是代码安全审查。
- **主题更新**
  - 入口：网站详情 → WordPress 组件 → 主题更新
  - 能力：逐个更新主题，更新当前启用的主题前需要额外确认，失败默认自动回滚。
  - 边界：没有主题批量更新；父主题和子主题不会作为一个整体更新。
- **单站插件批量更新**
  - 入口：网站详情 → WordPress 组件 → 批量更新插件
  - 能力：在一个网站内一次选择最多 50 个插件按顺序更新，开始前备份数据库。
  - 边界：某一项失败后暂停后续更新，需要人工回滚或忽略；不能跨多个网站批量更新。
- **更新备份与更新日志**
  - 入口：网站详情 → 更新备份 / 更新日志
  - 能力：查看更新专用备份（任务结束后保留 24 小时）和更新日志，处理中断或失败的更新。
  - 边界：恢复更新数据库备份只恢复数据库，不会回退插件、主题或核心文件。
- **临时维护窗口**
  - 入口：网站详情 → 文件保护与临时维护；WordPress 后台管理栏
  - 能力：对开启文件锁的网站，用专用维护密码临时开放 3–10 分钟写权限（可延长），到期或结束后自动恢复锁定并验证。
  - 边界：只解除文件锁，不影响数据库或 Nginx；面板重启会提前结束窗口并重新锁定。
- **WordPress 异常监控**
  - 入口：网站详情 → WordPress 优化 → 异常监控
  - 能力：每小时比较管理员账号、内容、关键设置、应用程序密码和数据库持久化对象的变化，发现新增管理员等异常时告警，帮助尽早发现入侵。
  - 边界：默认关闭；小时级抽样会漏掉期间发生又撤销的变化；被入侵的网站代码可能干扰结果；不是恶意代码扫描。

### 图片优化

- **新上传图片优化**
  - 入口：WordPress 后台 → WP Panel Optimizer → 图片优化
  - 能力：上传 JPEG/PNG 时重新压缩，或统一转换为 WebP。
  - 边界：只处理开启后的新上传；处理失败时保留原图；WebP 模式不保留原格式文件。
- **历史图片批量优化**
  - 入口：WordPress 后台 → WP Panel Optimizer → 图片优化 → 历史图库
  - 能力：在后台对 uploads 中已有的 JPEG/PNG 进行原地无损压缩。
  - 边界：不生成 WebP、不改文件名；原地处理，没有任务级备份。

### 文件管理

- **文件浏览、上传与下载**
  - 入口：文件管理
  - 能力：在网站目录内浏览、搜索、上传（大文件支持断点续传）、从 HTTPS 地址远程导入（最大 5GB）和下载文件。
  - 边界：范围限定在网站目录和数据库备份目录，不是全服务器文件管理器；没有在线代码编辑器。
- **文件操作、压缩与解压**
  - 入口：文件管理
  - 能力：复制、移动、重命名、删除、ZIP 压缩和解压，以及修复网站文件权限。
  - 边界：解压中途失败不会整体回滚；在线压缩包不是备份。

### 数据库

- **网站数据库管理**
  - 入口：数据库管理
  - 能力：每个网站自动对应一个 MariaDB 数据库和用户，随网站创建和删除；查看容量和备份情况，修改数据库密码（WordPress 网站同步更新 wp-config.php）。
  - 边界：不能单独创建与网站无关的数据库；面板没有内置 SQL 控制台，完整 SQL 操作通过按需 Adminer 完成。
- **按需 Adminer**
  - 入口：数据库详情 → Adminer
  - 能力：需要时为单个网站临时启动 Adminer（可设置 15/30/60 分钟后自动关闭），经过面板登录后访问。
  - 边界：拥有该站数据库账号的完整权限，没有只读模式、SQL 审计或自动备份。

### 备份

- **数据库备份与恢复**
  - 入口：网站详情 → 数据库备份；数据库详情；备份总览
  - 能力：手动或定时导出网站数据库，可下载、上传 SQL 文件恢复、从已有备份恢复，或清空数据库。
  - 边界：恢复前会删除现有数据表，且不会自动创建恢复前快照；需要保留当前数据时应先手动备份。
- **网站文件备份**
  - 入口：备份总览 → 文件备份；计划任务
  - 能力：定时或手动创建网站全量备份和 uploads 增量备份，自动轮转，可下载。
  - 边界：面板内没有一键文件恢复，需要下载后自行恢复；增量备份只包含 uploads 目录。
- **异地备份**
  - 入口：备份总览 → 远程备份设置
  - 能力：把数据库和文件备份通过 rsync/SSH 同步到另一台服务器，或上传到 S3 兼容对象存储，并核对远端状态、补传缺失文件。
  - 边界：不能直接从远端一键恢复，需要先下载再恢复。

### 安全防护

- **防火墙、限速与自动封禁**
  - 入口：安全设置；安全防御
  - 能力：组合 Nginx 规则与限速、Fail2ban 和 IPv4/IPv6 nftables：自动封禁高频请求、WordPress 登录爆破、敏感文件扫描和大量 404 探测、高置信度 SQL 注入 URL 以及 SSH 爆破，重复攻击阶梯延长封禁；识别冒充 Googlebot/Bingbot 的请求并记录告警；支持手动/永久封禁、白名单和搜索引擎官方 IP 白名单；默认拒绝未绑定域名的访问。
  - 边界：不是完整 WAF：SQL 注入规则只检查 URL，不检查 POST/JSON 请求体。
- **安全事件与代码完整性**
  - 入口：安全防御 → WordPress 安全事件 / 文件安全事件
  - 能力：汇总 WordPress 请求安全事件；对开启文件锁的网站建立代码 SHA-256 基线，每小时检查代码变化和运行目录中新出现的 PHP 文件并告警。
  - 边界：只告警和留证，不自动删除或隔离文件；初始基线不证明原有代码干净；未开启文件锁的网站没有代码完整性检查。

### 监控、日志与 AI 诊断

- **资源监控**
  - 入口：控制台；软件管理 → 服务状态
  - 能力：实时显示 CPU（单独显示 I/O 等待和 steal）、内存、磁盘和负载，保存 24 小时/7 天/15 天历史趋势；按网站显示 PHP-FPM 进程资源；守护受管服务并记录内存耗尽（OOM）事件。
  - 边界：历史最多保留 15 天；不是 APM 或时序数据库；按网站统计只包含 PHP-FPM 进程，不含数据库或网络。
- **告警通知**
  - 入口：告警通知；网站详情 → 运行监控
  - 能力：资源不足、服务异常、SSL 到期或续签失败、网站到期、网站无法访问、WordPress 异常等告警，可通过邮件（SMTP）或 Webhook 发送，每类可单独开关。
  - 边界：发送失败不会重试；网站可用性检测从本机发起，不是多地域监控；单站运行监控默认关闭。
- **日志分析**
  - 入口：日志分析
  - 能力：分析最长 7 天的网站访问日志：请求量、状态码、热门路径、访客 IP、爬虫和封禁情况，并可转入 AI 诊断深入分析。
  - 边界：单次最多读取 512MB 日志；统计结果不是精确的 PV 或真人访客数。
- **AI 诊断**
  - 入口：AI 诊断
  - 能力：汇总网站运行状态、日志和有限的代码片段，脱敏后发送给管理员自行配置的 OpenAI 兼容 AI 服务进行分析，并支持追问。
  - 边界：只读：只给出分析和建议，不会自动修改网站或服务器；需要自备 AI 服务，诊断数据会发送给所配置的服务商。

### 计划任务与软件管理

- **计划任务**
  - 入口：计划任务
  - 能力：用页面管理定时任务：Shell 命令、用系统 cron 替代 WordPress 自带的 WP-Cron、文件备份任务；支持立即执行和查看执行日志，网站暂停时其站点任务自动暂缓。
  - 边界：Shell 任务按管理员设定的身份执行任意命令，需要自行确认命令安全。
- **软件与服务管理**
  - 入口：软件管理
  - 能力：查看和启停 Nginx、PHP-FPM、MariaDB、Redis 等受管服务；编辑 PHP、Nginx、MariaDB、Redis 的关键配置（保存失败会恢复旧配置）并提供按硬件计算的推荐值；查看日志；安装 WP-CLI 和 Node.js 开发工具。
  - 边界：只管理固定的受管服务，不能安装其他软件栈（如 Apache、MySQL 或其他 PHP 版本）。

### 网站搬家

- **WP Panel 之间的网站搬家**
  - 入口：网站管理 → 网站搬家
  - 能力：在两台相同版本的 WP Panel 服务器之间搬迁 WordPress 或通用 PHP 网站，包括文件、数据库、域名与别名、SSL 证书和主要设置；可一次选择多个网站，搬家期间源站显示维护页面。
  - 边界：只支持 WP Panel 之间搬家，不能从其他面板导入；不迁移备份历史、访问日志、自定义 Nginx 规则和自定义命令任务；完成后需管理员自行修改 DNS 或 CDN 解析。

## 常见误解

- **误解**：所有网站使用同一个系统用户，一个网站被入侵就能读取其他网站的源码和配置。
  - **事实**：错误。每个网站有独立系统用户和独立 PHP-FPM 池，PHP 受 open_basedir 限制只能访问本站目录；wp-config.php 为 0600，只有本站用户可读。只有在攻击者绕过 PHP 限制并取得系统级执行能力时，才可能读取其他网站的普通代码文件，仍读不到其 wp-config.php。
- **误解**：所有网站共用一个 PHP 池，一个网站流量暴增会抢占其他网站的 PHP 进程。
  - **事实**：不准确。每个网站有独立 PHP-FPM 池和独立进程上限，一个网站用满进程不会占用其他网站的名额。但 CPU、内存、磁盘 I/O 和 MariaDB 是整机共享的，严重的流量高峰仍可能让其他网站变慢。
- **误解**：网站之间完全隔离，一个网站出问题绝对不会影响其他网站。
  - **事实**：言过其实。隔离覆盖系统用户、文件访问、数据库账号和 PHP 进程数，但整机资源、Redis 和全局 PHP 配置是共享的，也没有单站资源配额；这不是容器或虚拟机级隔离。
- **误解**：WP Panel 是宝塔、aaPanel 或 1Panel 的分支或换皮版本。
  - **事实**：错误。WP Panel 是独立开发的 Go 项目，以 GPL-3.0 开源，并且不能与这些面板装在同一台服务器上。
- **误解**：可以为不同网站选择不同的 PHP 版本。
  - **事实**：错误。所有网站固定使用 PHP 8.3，PHP 参数也是全服务器统一。
- **误解**：WP Panel 和通用面板一样提供邮件、DNS、FTP、Docker 和应用商店。
  - **事实**：错误。这些都不在 WP Panel 的范围内，它只专注于 WordPress 和通用 PHP 网站托管。
- **误解**：WP Panel 支持经销商、客户子账号和主机套餐，可以像 cPanel/DirectAdmin 一样卖主机。
  - **事实**：错误。面板只有一个管理员，没有多用户、配额或计费，适合管理员自己管理多个网站，而不是向多个客户出售共享主机。
- **误解**：面板可以一键恢复网站文件备份。
  - **事实**：不准确。数据库备份可以在面板内恢复；文件备份目前需要下载后自行恢复。
- **误解**：面板会自动批量更新所有网站的 WordPress、插件和主题。
  - **事实**：错误。更新由管理员逐站预览确认，带备份和失败回滚；插件可在单站内批量更新，但没有无人值守或跨站批量更新。
- **误解**：面板的 AI 诊断会自动修复网站问题。
  - **事实**：错误。AI 诊断只读，只给出分析和建议，不会修改网站或服务器，并需要管理员自备 AI 服务。
- **误解**：WP Panel 自带完整 WAF 和恶意代码扫描。
  - **事实**：错误。它提供 Nginx/Fail2ban/nftables 规则拦截与封禁、变化监控和代码完整性告警，但不检查请求体，也不扫描恶意代码或漏洞。
- **误解**：WP Panel 可以安装在 Ubuntu、CentOS 或通过 Docker 运行。
  - **事实**：错误。只支持在纯净 Debian 13 上原生安装，不使用 Docker。
- **误解**：一个 WP Panel 可以集中管理多台服务器。
  - **事实**：错误。每台服务器安装各自的面板；两台面板之间只能建立网站搬家连接。
- **误解**：每个网站都有独立的 Redis 实例或密码。
  - **事实**：错误。服务器只有一个 Redis 实例，网站之间只用键前缀区分，没有每站密码或 ACL。

## 对比维度（仅 WP Panel 一侧）

下表只描述 WP Panel。其他面板请以其官方文档为准。

| 维度 | WP Panel |
|---|---|
| 定位 | 单台 VPS 上的 WordPress 专用托管与运维面板，单管理员。 |
| 支持系统 | 仅 Debian 13，需要纯净服务器。 |
| 软件栈 | 固定 Nginx + PHP 8.3 + MariaDB + Redis，原生安装，无 Docker，不能替换组件或切换 PHP 版本。 |
| 网站类型 | WordPress（单站点）和通用 PHP。 |
| 站点隔离 | 每站独立系统用户、PHP-FPM 池、open_basedir、数据库和数据库用户；wp-config.php 为 0600。不是容器隔离。 |
| 资源限制 | 每站有独立 PHP 进程上限；没有 CPU、内存、I/O 或磁盘配额，整机资源共享。 |
| 多用户与经销商 | 不支持；只有一个管理员。 |
| 邮件、DNS、FTP | 均不提供；文件传输用网页文件管理器或单站 SSH/SFTP 开发访问。 |
| SSL | Let's Encrypt HTTP-01 自动申请与续签，支持手动证书；无通配符证书。 |
| 备份 | 数据库定时备份与面板内恢复；文件全量 + uploads 增量备份（下载后自行恢复）；rsync/SSH 或 S3 异地同步。 |
| WordPress 专项能力 | WP 总览、带备份与回滚的核心/插件/主题更新、FastCGI 缓存联动、文件锁与临时维护窗口、异常监控、管理员和密码找回管理、图片优化。 |
| 安全防护 | 随机入口 + 两层登录；Nginx/Fail2ban/nftables 自动与阶梯封禁、冒充搜索引擎爬虫识别、SQL 注入 URL 拦截、代码完整性告警。不是完整 WAF 或恶意代码扫描器。 |
| 迁移 | 两台 WP Panel 之间可多站搬家；从其他面板迁入需手动上传文件并导入数据库。 |
| 许可与价格 | GPL-3.0 开源，免费使用。 |
