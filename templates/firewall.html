安全防御规则说明

检测范围

自动封禁规则监控所有网站的 access.log 和 error.log；登录/XML-RPC 认证爆破单独读取 wp-login-security.log（不受站点「访问日志」模式影响，始终记录）；WordPress 可疑访问分析额外读取 wp-security.log，仅做本地统计和证据整理。

登录/XML-RPC 认证爆破 — 来源标注为「登录防护」（独立 jail，命中以下任一规则计为 1 次违规）

  • POST /wp-login.php 返回 HTTP 200 — 作为疑似登录失败计数；成功登录返回的 302，以及找回密码、重置密码、注册等明确合法动作不计入。部分二次验证或安全插件流程也可能返回 200，设置阈值时需考虑此类场景
  • POST /xmlrpc.php 返回 HTTP 403 — 仅在面板禁用 XML-RPC 时出现，视为无条件的攻击信号

判定依据是 Nginx 路由完成后已规范化的请求路径，任意数量的多余斜杠或 URL 编码变体（如 //wp-login.php、%2Fwp-login.php）只要最终被路由到登录/XML-RPC 入口，都会统一计数，不存在换个写法就不计数的空子。使用独立的 wppanel-login jail，和下方「Web防护」的全站限流/探测信号分开累计，互不影响触发阈值。

触发条件 — 来源标注为「Web防护」（命中以下任一规则计为 1 次违规）

  • 返回 HTTP 429 — 超出请求频率限制
  • 敏感文件扫描返回 404 — 如 .env、.git、wp-config.php、.sql、压缩包等

以上 2 条共用同一条 Fail2ban 规则（jail: wppanel），封禁列表「来源」列只会统一显示「Web防护」，无法从来源反查具体命中哪一条，可结合「原因」列或站点日志判断。

404 泛滥检测（独立规则，来源标注为「404防御」）

任意路径返回 404 达 30 次/60 秒 判定为目录扫描，固定阈值，不受下方自定义阈值影响。

与「Web防护」的敏感文件扫描规则存在重叠：命中 .env、.git 等敏感文件的 404 请求，会同时被两条规则计数，可能让同一 IP 先后出现「Web防护」和「404防御」两条来源的封禁记录。这是有意设计（精确规则阈值更低、触发更快），不是重复封禁。

WordPress 异常路径访问（仅记录，不产生「来源」）

写入 wp-security.log，用于「WordPress 可疑访问分析」标签页统计，不自动封禁，不会出现在封禁列表的「来源」列。

封禁阈值

「Web防护」的 2 条触发条件默认 60 秒内累计 5 次违规 → 自动封禁；「登录防护」的 2 条触发条件复用同一份阈值配置（均可在「安全设置」页面自定义阈值和统计窗口；自动封禁阶梯固定），但按独立 jail 累计，互不影响。

「404防御」固定为 30 次/60 秒，不开放自定义。

重复违规递增封禁

  • 同一 IP 在同一 jail 重复触发时，按 10 分钟 → 1 小时 → 6 小时 → 24 小时 → 7 天 递增，到期由 Fail2ban 自动解除
  • 「Web防护」「登录防护」「404防御」「SSH防护」分别计数；一个规则中的次数不会叠加到另一个规则
  • 违规历史由 Fail2ban 保留 30 天；超过保留期后，后续触发可能重新从首档计算
  • 自动规则最长封禁 7 天，不会自动升级为永久封禁；永久封禁仅由管理员手动执行

封禁列表记录 Fail2ban 实际给出的本次时长和累计次数；服务重启时恢复原有封禁，不会额外增加违规次数。

封禁机制

  • Fail2ban — 管理来源「Web防护」封禁（jail: wppanel）、来源「登录防护」封禁（jail: wppanel-login）、来源「404防御」封禁（jail: wppanel-404）和来源「SSH防护」封禁（jail: wppanel-sshd，复用与 Web防护相同的阈值，检测 /var/log/auth.log 中的 SSH 登录失败），到期自动释放
  • Nftables 持久 — 管理管理员手动永久封禁、来源「扫描防御」封禁（jail: panel_scan）和来源「面板」封禁（jail: panel），独立于 Fail2ban；有期限的记录到期解除，手动永久封禁需管理员解封
  • Nginx 黑名单 — 与 Fail2ban 联动，Web 防护 jail 封禁时同步写入 Nginx geo 黑名单，被禁 IP 直接返回 444（关闭连接），确保 Cloudflare 代理场景下也能有效拦截

三条通道同时生效：Nftables 拦截直连源站的请求，Nginx 拦截经 Cloudflare 转发的请求，Fail2ban 到期自动释放。

Cloudflare 场景说明

  • 面板自动部署 /etc/nginx/conf.d/wppanel-realip.conf，从 Cloudflare 的 CF-Connecting-IP 头部还原真实访客 IP
  • 白名单刷新时自动更新 Cloudflare 官方 IP 段，确保仅信任 Cloudflare 来源
  • 无需任何手动配置，检测到 Cloudflare 代理时自动生效

如需关闭 Nginx 层封禁：删除 /etc/fail2ban/action.d/wppanel-nginx.conf，并从 /etc/fail2ban/jail.d/wppanel.conf 中移除 wppanel-nginx action，然后 systemctl reload fail2ban && nginx -s reload。

扫描防御

  • 针对面板 8443 端口的扫描防护，不作用于网站端口（80/443）
  • 非浏览器特征请求（如 curl、脚本、扫描器）访问面板端口且未命中随机入口 → 封禁 30 天；常见浏览器系统探测路径和带 BasicAuth 头的请求不会直接触发扫描封禁
  • 命中随机入口（/{suffix}）的请求正常放行，不受影响

触发后写入面板封禁列表，来源标注为「扫描防御」，等级为临时 30 天。

面板登录防护

  • 面板登录页或 BasicAuth 连续 5 次认证失败（5 分钟窗口内）→ 封禁 24 小时
  • 只统计面板自身的认证请求，与上方针对网站访问的「Web防护」规则相互独立

触发后写入面板封禁列表，来源标注为「面板」。

手动封禁

管理员在本页面「手动封禁 IP」表单提交的封禁，不经过以上任何自动规则，来源标注为「手动封禁」。

白名单豁免

127.0.0.1、Cloudflare / Googlebot / Bingbot 官方 IP 段、自定义白名单 IP 不会被封禁。白名单在「安全设置」页面管理。

WordPress 安全日志路径白名单只排除正常所有权验证文件等路径，不影响 IP 封禁白名单。

请求频率限制原理

采用令牌桶算法：每 IP 一个桶，容量 = 突发缓冲（默认 300），按设置的「请求频率」持续补充令牌。请求到达消耗令牌，耗尽后超出持续速率的请求返回 429。默认 60 次/分钟时，长期速率约为 1 次/秒。

⚠ 多次 429 会被 Fail2ban 自动封禁。请确保突发缓冲足够日常使用。

✓ 较大的突发缓冲可减少正常页面并发请求误触发 429，但也会延后持续高频请求首次进入限速的时间；耗尽后的长期速率仍由「请求频率」决定。

服务器验证命令

SSH 登录服务器执行以下命令查看当前封禁状态：

# 查看网站防护封禁
fail2ban-client status wppanel
# 查看登录/XML-RPC 认证爆破封禁
fail2ban-client status wppanel-login
# 查看 404 泛滥封禁
fail2ban-client status wppanel-404
# 查看 SSH 暴力破解封禁
fail2ban-client status wppanel-sshd
# 查看 Nftables 持久封禁（扫描防御 + 面板认证封禁）
nft list set ip wppanel_persist banned_ips
