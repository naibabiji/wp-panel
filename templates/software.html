WordPress 配置建议（按站点复杂度分档）

以下为保守建议值，确保系统稳定不 OOM，按站点复杂度（而非硬件规格）分档，可在软件管理中根据实际需求调大。OPcache、MariaDB、Redis 这类跟服务器硬件规格相关的参数，请直接使用下方软件管理页对应卡片里的"重新计算推荐值"按钮——那是根据这台服务器实际内存/CPU/站点数现算的，比这张静态表格更准确。

适用场景 PHP memory_limit upload / post
简单博客 / 展示站 128M 32M / 32M
多插件站 / 普通企业站 256M 64M / 64M
电商 / Elementor 等重度页面构建器 512M 128M / 128M
大型多站点 / 高负载 512M 256M / 256M

通用原则

  • post_max_size 必须 ≥ upload_max_filesize，Nginx client_max_body_size 需保持一致
  • max_execution_time 建议统一 300，导入数据或批量处理时临时调至 600
  • max_input_vars 面板默认已是 10000，覆盖绝大多数场景，通常无需调整；只有单页面字段数量极多（如超大型 Elementor 页面）时才需要继续调大
  • OPcache（opcache.memory_consumption / opcache.max_accelerated_files）、MariaDB innodb_buffer_pool_size、Redis maxmemory 都跟服务器硬件规格和站点数量相关，请用软件管理页对应卡片的"重新计算推荐值"按钮获取针对这台服务器的准确建议，不要套用固定数值
